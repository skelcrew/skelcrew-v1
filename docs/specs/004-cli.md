# 004 — CLI

## Goal

Give the owner, and every agent, a way to use skelcrew from a shell: file a card in one line,
see the cards as rows with a phase track, open one to read its spec and activity, comment,
and move it through the gates. This is the one client — the CLI is how an agent in a live
session files a card and how a runner-spawned agent posts to its card, identified as an agent
member with the same commands the owner uses. `AGENTS.md` sets the bar: adding a card must
cost less than opening a terminal tab.

## Current behavior

`packages/cli/src/main.ts` prints `skelcrew <version>` and exits; `packages/cli/package.json`
depends on `@skelcrew/shared` and declares no `bin`. Nothing parses arguments, nothing
connects to anything.

The daemon side is 003 (`docs/specs/003-client-protocol.md`), in flight as this is written:
a unix socket at `<repo root>/.skelcrew/skelcrew.sock` (or `$SKELCREW_DIR/skelcrew.sock`),
newline-delimited JSON-RPC, a `hello` that binds the connection to the owner or to a named
agent member, methods mirroring the 002 core one to one (`createCard`, `listCards`,
`getCard`, `moveCard`, `setBody`, `comment`, `setRefs`, `archiveCard`, `activitySince`,
`listMembers`), a `subscribe` stream, an error table mapping `CoreError` codes to JSON-RPC
codes with `error.data.code`, and a client in `@skelcrew/shared`: `connect(socketPath,
hello)` resolving to `{ call, subscribe, unsubscribe, close }`. 003 also owns repo-root and
data-directory discovery in `packages/daemon/src/server/paths.ts`. This spec is written
against 003's contract, not its implementation; if 003's review changes a shape, the change is
mirrored here before this spec is developed.

The model is 002: `Card` (`id`, `title`, `body`, `phase`, `refs`, `archivedAt`, timestamps),
`CardDetail` with `activity`, `Member`, the typed `Activity` union, and `PHASES` with display
names, all in `packages/shared/src/`. Every size cap is exported from `shared`.

`docs/MILESTONES.md` carries three things into this spec: the CLI is the one client for
owner and agents (`--as <name>`, `--json`); bulk filing from stdin so a milestones file
becomes cards in one command; and the attention queue and the ping are 010's, not this
spec's. The spike's finding that "the card spec view is a primary review surface" applies:
`show` has to put the whole body in front of the reader.

## Desired behavior

`skelcrew` is `bun packages/cli/src/main.ts` (root script `bun run skelcrew -- …`, and the
package declares a `bin` so `bun link` installs the command). Every command connects to the
daemon's socket, does one thing, prints, and exits. Nothing is stored client-side.

### Identity

Without `--as`, the CLI speaks as the owner. With `--as <name>` or the environment variable
`SKELCREW_AS=<name>`, it speaks as that agent member, creating it on first use through
`hello`. The flag wins over the variable. Every mutation the CLI makes is therefore
attributed to the right member in the card's activity, and an agent hits the same gates a
human would not.

### Commands

- `skelcrew add <title> [--body <text> | --body-file <path>]` files one card and prints its
  id and title. With no `<title>` argument and stdin not a terminal, it reads stdin and files
  one card per non-empty line, in order, printing one line per card; a line that fails
  (over the title cap, say) is reported on stderr with its line number and filing continues,
  exiting non-zero at the end.
- `skelcrew ls [--all]` prints one row per card, oldest first: the id, a five-cell phase track
  with the current phase marked, the phase's display name, and the title. `--all` includes
  archived cards, marked as such. An empty list prints one line saying so and a hint to `add`.
- `skelcrew show <id>` prints the card: id, title, phase, refs (branch, commits, PR URL, only
  those set), created and updated times; then the body verbatim, in full, as the markdown it
  is; then the activity oldest first, one line per event with its time, actor name, and a
  one-line summary — comments print their full text.
- `skelcrew comment <id> [<text>]` posts a comment; with no `<text>`, reads stdin.
- `skelcrew mv <id> <phase> [-m <text>]` moves the card; `<phase>` is a phase id
  (`idea`, `spec`, `code`, `pr`, `done`), case-insensitive. With `-m`, the comment is posted
  after a successful move, so "send back with feedback" and "approve with a note" are one
  command. A rejected move posts nothing.
- `skelcrew body <id> [--file <path>]` replaces the body from the file or from stdin.
- `skelcrew refs <id> [--branch <name>] [--pr <url>] [--commit <sha>]...` sets references;
  at least one flag is required.
- `skelcrew archive <id>` archives the card.
- `skelcrew --version` prints the version; `skelcrew help` and `skelcrew <command> --help`
  print usage.

### Output and errors

- `--json` on any command prints exactly what the daemon returned for that command as one
  JSON document on stdout and nothing else: the card for `add` (an array for bulk), the
  array for `ls`, the `CardDetail` for `show`, the event for `comment`, the card for `mv`,
  `body`, `refs`, `archive`.
- Human output goes to stdout; errors go to stderr as one line starting with `error:`,
  followed by the daemon's message. Exit codes: 0 success, 1 the daemon refused
  (`not_found`, `forbidden`, `invalid`, `conflict`) or could not be reached, 2 usage error
  (unknown command, missing argument, bad phase, no flag for `refs`).
- When no daemon is listening on the resolved socket path, the error names the path and says
  to run `bun run daemon` from the repository.
- Times print in the local timezone as `YYYY-MM-DD HH:MM`. Ids print as `#12`.

## Implementation approach

### Where it lives

- `packages/cli/src/main.ts` — entry: parse argv, resolve identity and socket path, connect,
  dispatch to one command, print, exit. The 001 wiring test keeps importing `VERSION` from
  `@skelcrew/shared`; that import moves to serve `--version`.
- `packages/cli/src/commands/` — one module per command taking the connected client and
  parsed arguments, returning the daemon result; formatting separated from fetching so
  `--json` is the same code path minus the renderer.
- `packages/cli/src/render.ts` — the row, the phase track, the card view, the activity line.
- `packages/shared/src/paths.ts` — repo-root walk, `SKELCREW_DIR`, and the socket and
  database paths, moved here from `packages/daemon/src/server/paths.ts` so the CLI and the
  daemon resolve the same path from the same code. The daemon imports it; its own behaviour
  and 003's tests are unchanged.
- `packages/cli/package.json` — `"bin": { "skelcrew": "./src/main.ts" }`; no dependencies
  added.
- Tests colocated as `*.test.ts`: the daemon's `startServer` from 003 in-process on a temp
  socket path, the CLI run as a subprocess (`Bun.spawn` on `packages/cli/src/main.ts` with
  `SKELCREW_DIR` pointing at the temp directory), assertions on stdout, stderr, and exit
  code. Unix socket paths are limited to about 104 bytes on macOS, so temp directories go
  directly under the OS temp dir.

### Decisions resolved from repository context

- **Verbs mirror the core, not a workflow vocabulary.** `add`, `ls`, `show`, `comment`,
  `mv`, `body`, `refs`, `archive` are the 002 mutations and reads with shell-length names.
  There is no `approve`, `reject`, or `done` command: `docs/MILESTONES.md` settled that a
  gate is a move and feedback is a comment plus a move, so `mv <id> code -m "…"` is approval
  and `mv <id> code -m "…"` from `pr` is send-back. One verb, no second vocabulary to keep in
  sync with the phase names.
- **Identity by flag and environment variable, nothing stored.** `AGENTS.md`: agents are
  members using the same primitives, and the CLI is the one client. `--as` is what an agent
  in a live session types; `SKELCREW_AS` is what the runner sets at spawn (006/007) so a
  playbook's commands need no flag. Both go straight into 003's `hello`. The variable name is
  fixed here so 006 does not invent one.
- **`--json` returns the daemon's result verbatim.** Agents parse rather than scrape, and the
  shapes are already documented once, in `shared`. No CLI-specific JSON envelope.
- **Bulk filing reads lines, not markdown.** A milestones file has a shape only this repo
  uses; one title per line is what `grep`, `cut`, and an agent can all produce. Filing
  continues past a bad line so one over-long title does not lose the rest, and the non-zero
  exit says something was skipped.
- **`mv` moves first, then comments.** A rejected move with a stray feedback comment would
  read as if the feedback had been acted on. Moving first means the comment only exists when
  the move did.
- **`show` prints the body raw.** No markdown renderer: it is the same text the author
  wrote, it pipes into a pager or an editor cleanly, and the spike's finding was about room
  and fidelity, not about styling. Rendering is a TUI concern.
- **Path discovery moves to `shared`.** The CLI must find the socket the daemon created;
  duplicating the walk in two packages is how they drift. `shared` already holds the client
  after 003, so it is the established home for code both sides need. The daemon's behaviour
  is unchanged by the move; 003's path tests keep passing against the re-exported functions.
- **No argument-parsing dependency.** `node:util`'s `parseArgs` is available under Bun
  (verified on 1.3.14) and covers flags, values, and positionals. The repo has no runtime
  dependencies and this spec adds none.
- **No daemon auto-start.** When the socket is dead the CLI says which command to run. Starting
  a background process from a client is a lifecycle decision that belongs with the daemon
  (006 or later), and a surprising one to make silently.
- **Exit codes 0/1/2** follow the common shell convention (success, operation failed, usage).
  Distinguishing `forbidden` from `not_found` is what `--json` and the stderr message are for.

## Acceptance criteria

1. `bun run check` exits 0 with tests under `packages/cli/src/` beyond 001's wiring test.
2. `bun packages/cli/src/main.ts --version` prints `skelcrew <version>` where `<version>`
   equals `VERSION` from `@skelcrew/shared`; `packages/cli/package.json` declares
   `bin.skelcrew` pointing at `src/main.ts`; no `package.json` gains a dependency.
3. With a daemon serving a temp `SKELCREW_DIR`, `skelcrew add "First card"` exits 0 and
   prints a line containing `#1` and `First card`; `skelcrew add "Second" --body "hello"`
   prints `#2`; `skelcrew ls` prints two rows, in id order, each with the id, a phase track,
   the phase name `Idea`, and the title. `skelcrew ls --json` prints a JSON array of two
   cards equal to what `listCards` returns.
4. `printf 'a\nb\n\nc\n' | skelcrew add` files three cards titled `a`, `b`, `c` in that
   order and prints three lines. With a fourth line over the title cap, the CLI files the
   other three, prints an `error:` line on stderr naming line 4, and exits 1.
5. `skelcrew show 1` prints the title, `Idea`, the created time, the body verbatim (a
   multi-line body with markdown headings appears unchanged), and the activity with a
   `card_created` line naming the owner. After `skelcrew comment 1 "looks good"` the activity
   gains a line containing `looks good` and the owner's name. `skelcrew show 1 --json` prints
   the `CardDetail`.
6. `skelcrew comment 1` with `looks fine` on stdin posts that comment. `skelcrew comment 1`
   with empty stdin exits 1 with an `error:` line.
7. `skelcrew mv 1 spec` as the owner exits 0 and `show 1` reports `Spec`. `skelcrew mv 1 CODE
   -m "approved"` moves to `code` and the activity then shows the move followed by the
   comment `approved`. `skelcrew mv 1 pr -m "note" --as crew-1` succeeds and the move and
   comment are attributed to `crew-1`. `skelcrew mv 1 code -m "send back" --as crew-1`
   (leaving `pr`) exits 1 with an `error:` line containing `forbidden`, the card stays in
   `pr`, and no comment `send back` exists.
8. `skelcrew mv 1 review` exits 2 with a usage error listing the five phase ids.
   `skelcrew mv 999 spec` exits 1 with an `error:` line containing `999`. `skelcrew frob`
   exits 2.
9. `SKELCREW_AS=crew-2 skelcrew comment 1 "hi"` attributes the comment to `crew-2`;
   with `--as crew-3` as well, to `crew-3`. `skelcrew ls --json` afterwards shows nothing
   about members, but `show 1 --json` activity entries carry `crew-2`'s and `crew-3`'s ids
   and `show 1` renders their names.
10. `printf '# Goal\n\nx\n' | skelcrew body 1` sets the body, and `skelcrew body 1 --file
    <path>` sets it from a file; `show 1` prints it verbatim both times. A body over the cap
    exits 1 with an `error:` line.
11. `skelcrew refs 1 --branch feat/x --pr https://github.com/o/r/pull/1 --commit abcdef0
    --commit 1234567` sets all three and `show 1` prints them; `skelcrew refs 1` with no
    flag exits 2; `--pr http://…` exits 1.
12. `skelcrew archive 2` exits 0; `ls` no longer shows `#2`; `ls --all` shows it marked
    archived; `show 2` still works.
13. With no daemon on the resolved socket path, every command exits 1 with an `error:` line
    naming the socket path and containing `bun run daemon`. With no `SKELCREW_DIR` and no
    `.git` in any ancestor of the working directory, the error says so and exits 1.
14. Run from a subdirectory of a git repository whose root has a daemon listening on
    `.skelcrew/skelcrew.sock`, `skelcrew ls` reaches that daemon.
15. `--json` output on every command is a single parseable JSON document and nothing else on
    stdout, on success; on failure stdout is empty and stderr has the `error:` line.
16. `packages/daemon/src/server/paths.ts` no longer defines path resolution itself; it
    re-exports or imports from `packages/shared/src/paths.ts`, and 003's path tests pass
    unchanged.
17. `docs/MILESTONES.md`'s status section records `SKELCREW_AS` as the variable the runner
    sets, so 006 and 007 build on it.

## Tests

All through observable behavior: the daemon started in-process on a temp socket, the CLI
run as a subprocess with `SKELCREW_DIR` set, and assertions on its stdout, stderr, and exit
code. No test touches the repository's `.skelcrew/` or any path under the repo.

- Each command's happy path and its `--json` form, against the daemon's own result for the
  same call.
- Bulk `add` from stdin, including the partial-failure exit.
- Identity: owner by default, `--as`, `SKELCREW_AS`, flag beating variable, attribution
  visible in `show`.
- Gates through the CLI: an agent's forbidden move exits 1, the card is unmoved, and the
  `-m` comment is not posted.
- Usage errors exit 2 and daemon errors exit 1, with stdout empty.
- Dead socket and no-repository messages; socket discovery from a subdirectory of a temp git
  repository.
- 003's path tests continue to pass after the move to `shared`.

The 001 wiring test in `packages/cli/src/main.test.ts` remains and must pass. Red for this
spec is the first command test failing because `bun packages/cli/src/main.ts ls` prints the
version line and exits.

## Out of scope

- The attention queue, `watch`, a live activity tail, and the ping: 010.
- Claims and leases (`claim`, `heartbeat`, `release`): 009, which adds their wire methods
  and their commands together.
- Starting the daemon from the CLI, daemonizing it, or checking its version against the
  client's beyond what `hello` returns.
- Markdown rendering, colour, paging, or interactive editing (`$EDITOR`); `body` takes a
  file or stdin.
- Filtering or sorting `ls` beyond `--all`; searching; showing members.
- Editing a title, unarchiving, or deleting.
- Global installation beyond the `bin` field (`bun link` is the user's step; no installer,
  no release artefact).
- A TUI. The row and phase-track rendering here is plain text and is not the TUI's.
