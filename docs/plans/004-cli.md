## Decisions the spec left open

- **What moves to `shared` is discovery, not lifecycle.** `prepareDataDir` (mkdir + chmod)
  and `daemonAnswers` (which deletes a stale socket file) are things only the daemon may
  do; a client must never remove a socket file. They stay in the daemon's `paths.ts`, which
  now imports the discovery half from `shared`.
- **Two parses.** `parseArgs` runs once loosely to find the command word, then strictly
  with that command's option table merged with the global one (`--as`, `--json`, `--help`,
  `--version`), so an unknown flag or a flag missing its value is a usage error (2) with
  the command's usage line on stderr.
- **A command's `run` returns the daemon result and a closure that renders it.** `--json`
  prints `JSON.stringify(result)` and never calls the closure; `show` needs `listMembers`
  for actor names, which the closure captures without the JSON output changing shape.
- **Ids accept `1` or `#1`**, since `#1` is how the CLI prints them.
- **`add` in bulk mode with nothing on stdin is a usage error (2)**: no title anywhere.
  `--body` with `--body-file` is a usage error too.
- **`mv -m` when the move succeeds but the comment fails** exits 1 with an `error:` line
  saying the card was moved but the comment was not; stdout stays empty.
- **Dead socket is not distinguished from missing socket**: both are "no daemon is
  listening on <path>; run `bun run daemon` from the repository". The file is left alone.
- **Rendering**: phase track is `●○○○○` with the current phase filled; `ls` rows are
  `#id  track  Phase  title`, archived rows end in `(archived)`; `show` prints a header
  block (title, phase, refs that are set, created, updated), a blank line, the body raw, a
  blank line, then `YYYY-MM-DD HH:MM  actor  summary` per event, with a comment's text
  verbatim after `commented:`.

## Review round 1

Two Important findings and two Minors fixed; judgement calls (a)–(h) stand as reviewed.

- **Important 1 — unreadable `--body-file` / `--file` printed a stack trace.** `readFileSync`
  ran inside `parse()` and only `UsageError` was caught there. Now `commands/command.ts`
  has `readFile(path)`, which wraps the read and throws `UsageError("cannot read <path>:
  <reason>")`; `add` and `body` use it, so the failure is one `error:` line and exit 2 (an
  unusable argument, caught before anything connects). The `parse()` catch also no longer
  rethrows: any other error there is an `error:` line and exit 1, never a stack dump.
  Test: "an unreadable --body-file or --file is one error line, not a stack trace".
- **Important 2 — an empty identity fell open to the owner.** `asName ? agent : human`
  turned `--as ""` and `SKELCREW_AS=""` into the owner. Now only an absent flag and an
  unset variable mean the owner: `--as ""` is a usage error (exit 2, nothing sent), and a
  set-but-empty `SKELCREW_AS` goes to `hello` verbatim, where the daemon's `invalid`
  refuses it (exit 1). A real `--as` still wins over an empty variable. Test: "an empty
  identity fails closed".
- **Minor 3 — all-failed bulk `add` wrote a bare newline.** `main.ts` skips the stdout
  write when the rendered text is empty. Asserted in the bulk-add test.
- **Minor 5 — the tests never checked which track cell was marked.** `TRACK` is now the
  exact string per phase; the add test asserts `●○○○○` and the mv test asserts `○●○○○`
  after `mv 1 spec` and `○○●○○` after `mv 1 CODE`.

Minors 4 and 6 are carried to the PR per the coordinator.
